## Original Problem

An autonomous revenue-recovery agent for Indian payments deciding *whether, when, how and in what
language* to intervene on at-risk revenue — and reporting **incremental** rupees recovered against
a randomised no-contact holdout, with every outbound action gated by a deterministic compliance
kernel emitting a signed certificate.

## Actual Architecture (from code)

`src/recovery_ledger/` — 15 packages: `detector`, `diagnoser`, `policy`, `executor`, `kernel`,
`ledger`, `listener`, `negotiation`, `events`, `sim`, `live`, `llm`, `agent`.

- **Kernel** (`kernel/engine.py`, `kernel/certificate.py`, `kernel/provenance.py`, `kernel/rules/`)

- **Ledger** (`ledger/ledger.py`) — hash-chained append-only log with `verify_chain_detail()`.

- **32 test modules** in `tests/`.
- **Experiments** — `tier1_criteo/`, `tier2_simulation/`, `ope_deployment/`, `sensitivity/`,
  `fairness/`, `fleet/`, `listener_eval/`, `negotiation/`; plus a `redteam/` directory.

### This is the only repo in the shortlist that defeats the circularity problem

`RESULTS.md` splits claims into two kinds and refuses to conflate them:

| Claim | Evidence base |
|---|---|
| **Method validity** — the causal machinery recovers known treatment effects | **Real randomised public data** (Criteo, Hillstrom) |
| **Policy dominance** — this policy beats named alternatives | **Simulation, under stated assumptions** |

The Tier-1 gate: before anything touches the simulator, the uplift learners and off-policy
estimators must reproduce effects already known from genuinely randomised experiments. Reported:
S/T/X-learner and causal forest Qini all positive on both datasets; IPS and SNIPS reproduce the
datasets' own arm-mean ATE **exactly** (+0.0451 Hillstrom, +0.0094 Criteo) without ever seeing the
direct arm comparison.

**This is the correct answer to the single most common fatal flaw in this field** — a synthetic
simulator whose labels are generated by the same rule the model learns. The builder names the
attack explicitly (N5: "Directly defeats 'your synthetic number is circular'").

### Deliberate non-use of AI — mechanically enforced (VERIFIED)

`tests/test_kernel_no_llm_imports.py` — **AST-parses** every `.py` under `kernel/` and fails the
build if any imports `anthropic`, `openai`, or `recovery_ledger.llm`. Two details show real care:
- It parses the AST rather than grepping, "so it can't be defeated by a comment or a docstring
  that happens to mention a banned name" (`:5-8`).
- `:42` — `assert py_files, "no .py files found under kernel/ — test would pass vacuously"`. An
  explicit **vacuity guard**.

The README carries a full "where AI is used and where it is deliberately not" table, with the three
NO rows — treatment-effect estimation, compliance decisions, money-affecting final actions — argued
individually. This is a direct, deliberate hit on rubric pillar 3.

### Audit trail is real and adversarially tested (VERIFIED)

`tests/test_ledger_tamper.py:1-8` opens by naming the failure mode most people miss:
> "`verify_chain()` returning False is easy to write and easy to write *wrongly* — a function that
> always returns False passes a naive test. These tests pin both directions."

It then tests untouched-chain-verifies, empty-chain-verifies, and each distinct tampering mode
caught **at the right entry with the right diagnosis** (`test_editing_a_payload_is_caught_at_that_entry`
asserts `broken_at == 3`).

### Stopping rules are real (VERIFIED)

`tests/test_all_stopping_rules.py` — 11 individually-tested rules (`resolved`, `opt_out`,
`budget_exhausted`, `negative_ev`, `do_not_disturb`, `promise_to_pay` (pauses rather than
terminating), `dispute_raised`, `human_escalation_threshold`, `hard_decline`, `regulatory_ceiling`,
`global_kill_switch`) — **plus `test_every_stopping_rule_is_reachable:197`**, a coverage guard
proving no rule is dead code.

## Candidate Patterns

### P1 — Two-Tier Validation: real RCT data before synthetic `EVALUATION_PATTERN` — **SELECT, top of field**
- **Source:** `RESULTS.md` Tier 1; `experiments/tier1_criteo/`, `experiments/tier1_*`
- **What:** prove the causal/measurement machinery on a **genuinely randomised public dataset**
  where ground truth is known, as a kill-gate, *before* pointing it at your own synthetic world.
- **Why strong:** it converts "my synthetic number is circular" from a fatal objection into a
  pre-answered one. It is the highest-leverage single move available for any measured claim.
- **Razorpay applicability:** T02 (precision/recall), T03 (money recovered), T04 (match rate). Any
  number we report over synthetic data is vulnerable to this exact attack.
- **Reimplement:** pick a public dataset with real randomisation or real labels in the same shape
  as our problem; run our estimator on it; assert it recovers the known answer; only then run our
  own data. Publish both tiers separately and never merge them.
- **Risks:** finding a genuinely analogous public dataset is the hard part; a poor analogy is worse
  than none because it launders false confidence.
- **Score: 10/10**

### P2 — Mechanically-Enforced AI Exclusion Zone `ARCHITECTURE_PATTERN` — **SELECT**
- **Source:** `tests/test_kernel_no_llm_imports.py`
- **What:** designate a module where LLMs are forbidden (compliance / money-final-action), then
  enforce it with an AST-walking test that fails the build — including a vacuity guard.
- **Why strong:** rubric pillar 3 asks "where you chose *not* to use one." Most repos answer with a
  README paragraph. This answers with a failing build. It is cheap (~50 lines) and unusually
  persuasive to an engineer.
- **Score: 10/10**

### P3 — Both-Directions Tamper Test `FAILURE_HANDLING_PATTERN` — **SELECT**
- **Source:** `tests/test_ledger_tamper.py`
- **What:** for any verifier, test that it accepts valid input *and* rejects each distinct invalid
  input at the right location — because `return False` passes a naive negative-only test.
- **Why relevant:** "show the audit trail" appears in two track bars. A hash chain nobody tested in
  the positive direction is theatre.
- **Score: 9/10**

### P4 — Incremental-vs-Gross Accounting with a No-Contact Holdout `SOLUTION_PATTERN` — **SELECT**
- Report incremental ₹ against a randomised holdout, never gross. Publish the holdout's unaided
  recovery rate (here 15.47%) as the number gross reporting silently claims.
- Directly answers T03's "show measured money recovered across a batch."
- **Score: 9/10**

### P5 — Stopping-Rule Reachability Guard `COMPONENT_PATTERN` — SELECT
- `test_every_stopping_rule_is_reachable` — proves no declared rule is dead code. Cheap; kills the
  "you listed 11 rules but only 3 can fire" objection instantly.
- **Score: 8/10**

## Rejected Patterns
- **The full 15-package agent decomposition.** Detector/diagnoser/policy/executor/listener/
  negotiation/fleet is more surface than a 10-day build needs; the negotiation and fleet modules
  are the thinnest and add the least per line.
- **The bold rupee headline.** Even correctly qualified, leading with a simulated ₹ figure invites
  the exact scrutiny the rest of the repo works so hard to survive.
